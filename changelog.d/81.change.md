A caller holding both an `ssh-shell` and an `ssh-port-forwarding` grant for the same username now receives `permit-port-forwarding` on their shell certificate, where shell issuance previously hardcoded it off. The two grants describe one set of capabilities for one session, so they are now evaluated together.

Stored `ssh-shell`, `ssh-port-forwarding` and `ssh-command` grants are rewritten to `ssh` by a database migration. `pfa grant ssh` replaces `pfa grant ssh-shell`, `pfa grant ssh-port` and `pfa grant ssh-command`, which are removed; use `--capability` to name capabilities explicitly (a legacy `ssh-shell` grant is equivalent to `--capability shell pty user-rc`, plus `agent-forwarding` and `x11-forwarding` where those were permitted). The legacy shapes are still accepted on the wire so that older clients can still write, but are normalized to `ssh` when stored and so read back as `ssh`. Upgrade `pfa` and `pfat` alongside the server: older clients cannot parse the new grant type when reading roles and boundaries.
