Add per-grant max ttl session duration field

Enforce the grant's session TTL on shell and exec SSH sessions (sftp is not reachable
through `pf ssh` today). Certificates now carry the computed session deadline and a
connection id; a PAM hook installed by `pf openssh host-init` terminates the login once
the deadline passes. Requires systemd/logind on the host; hosts initialized before this
release need `host-init` re-run to pick up the PAM wiring.

Also enforce the grant's session TTL on port-forwarding connections routed through a
bastion, closing the one gap the PAM hook above cannot cover: `ssh -L`/`-R` never opens a
PAM session, so it was previously unbounded. The bastion relay now requires every tunnel
(shell and port-forwarding alike) to present a signed, single-use token before bridging
to the local host, and force-closes port-forwarding tunnels once their deadline passes.
This is a breaking wire change: hosts must run this release's `pf bastion register` (and
clients this release's `pf`) for bastion-routed connections to keep working.
