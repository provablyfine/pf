`ssh` grants gain `max_session_ttl_s`, a per-capability bound on session duration in seconds, settable with `pfa grant ssh --max-session-ttl` and in the `pfat` grant editor. It is the one ordered dimension of the permission model, so it does not follow the set operations the other three fields do: a role grant *raises* the bound, a boundary ceiling and a deny *lower* it, and `null` means unbounded. A deny that names a bound therefore denies only the excess — it clamps rather than removes — while a deny with `max_session_ttl_s: null` removes the capability outright, as before.

**The bound is recorded and resolved, but not yet enforced.** Nothing stamps it onto a certificate or ends a session at the deadline, so setting it does not currently shorten any session. Enforcement follows in a later release.

The field is required on every `ssh` grant, like the other three: a stored grant is a security document, and a default would be invisible semantics for whoever reads it. Existing grants are updated to `null` by a database migration, and `pfa`/`pfat` must be upgraded with the server.
